## Intuition: Open-Book Exams Beat Memorization

Fine-tuning cannot inject rapidly changing facts or per-user permissions reliably. **<GlossaryTerm term="Retrieval-Augmented Generation">RAG</GlossaryTerm>** turns LLM generation into an open-book exam: retrieve the top-$k$ relevant document chunks at query time, ground the prompt strictly in those passages, and cite sources.

Single-stage vector search often misses exact part numbers, API flags, or acronyms (`ERR_KV_404`). Production pipelines use **Hybrid Search** (dense embeddings + sparse keyword BM25) followed by a **Cross-Encoder Reranker**!

<Callout type="tip" title="Agentic RAG Pattern">
  Rather than running one fixed vector query per prompt, **Agentic RAG** exposes retrieval as a tool (`search_knowledge(query)`). The model can decompose multi-hop questions, rewrite vague queries, inspect snippets, and re-query before answering.
</Callout>

<Callout type="math-deep-dive" title="Reciprocal Rank Fusion (RRF)">
  Because BM25 scores ($[0, 30]$) and cosine similarities ($[-1, 1]$) live on incompatible scales, RRF merges rankings purely by rank position $r_i(d)$:

  <Math tex="\text{RRF}(d) = \sum_{i} \frac{1}{k + r_i(d)}, \qquad k = 60" display />
</Callout>

    scores = {}
    for ranked_docs in rank_lists:
        for rank, doc_id in enumerate(ranked_docs, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)

    if chunk_size <= overlap:
        raise ValueError("chunk_size must exceed overlap")
    step = chunk_size - overlap
    chunks = []
    i = 0
    while i < len(text):
        chunks.append(text[i : i + chunk_size])
        if i + chunk_size >= len(text):
            break
        i += step
    return chunks`}
