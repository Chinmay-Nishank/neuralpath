## Intuition: Python as the Orchestrator, Not the Inner Loop

Machine learning libraries are written in C, C++, and CUDA—not pure Python. Python acts as the clean **control plane** that loads data, constructs model graphs, and logs metrics, while compiled numerical kernels perform the arithmetic.

<Callout type="warning" title="Avoid Mutable State Bugs in Training Loops">
  Using mutable defaults like `def add_sample(x, buf=[]):` or mutating a shared batch dictionary in place across epochs causes subtle leakage and non-reproducible training runs. Always create fresh containers or copy explicitly.
</Callout>

## Visual Check: Vector Spaces Behind Python Lists

When you convert Python lists of numbers into arrays, each sample becomes a coordinate vector that linear transformations can rotate and scale in one shot.

<Callout type="math-deep-dive" title="Time Complexity of Python Loops vs. Vectorized Dot Products">
  A Python `for` loop executes dynamic type checks, reference counting, and bytecode dispatch for every element $i = 1 \dots N$. Vectorized <GlossaryTerm term="Vectorization">vectorization</GlossaryTerm> pushes the loop inside contiguous C memory with SIMD instructions, often delivering 20x–100x speedups on $N = 10^5$ elements.
</Callout>
